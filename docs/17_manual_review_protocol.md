# Manual review

Review is structured data. A queue item records object/issue, immutable JSON candidate documents, a machine suggestion plus mandatory model invocation if any, source provenance, neighboring periods, status, timezone-aware creation time, parser/schema context, and whether second review is required. Each append-only adjudication stores source-language decision, a structured action and optional JSON payload, rationale, evidence provenance, reviewer/timestamp, versions, supersession, and paired second-review fields. Self-supersession, naive timestamps, same-person second review, and incomplete second-review pairs fail validation. Ambiguous linkage, split/merge, code conflict, source contradiction, casualty attribution, geography, semantic disagreement, or table row shifts may trigger review. Critical identity, casualty, and benchmark-total decisions require second review. Cross-record enforcement that a required second review is present belongs to materialization QA before the first operational review workflow.
