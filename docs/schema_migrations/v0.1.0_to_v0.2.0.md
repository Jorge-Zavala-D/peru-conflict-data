# Schema migration: v0.1.0 to v0.2.0

Status: migration specification only; no corpus records exist in this repository.

`v0.1.0` is the retained Milestone 0 snapshot. `v0.2.0` is the source-evidenced
working contract for the future M1/M2 baseline. A record is not upgraded by changing
its `schema_version` string. A migration must validate every mapping, retain the source
evidence, and route ambiguous or contradictory mappings to review.

## Version and registry changes

- Change the version literal from `0.1.0` to `0.2.0` only in newly generated records.
- Add the `mediation_process` registry entity and retain `dialogue_event`.
- Add controlled pipeline-origin values `source_reported` and `derived` for monthly
  indicators. These are not historical source taxonomies.
- Preserve every JSON Schema file under `schemas/v0.1.0/` unchanged.

## Field mappings

| v0.1.0 field | v0.2.0 treatment | Migration rule |
|---|---|---|
| `demand.theme_original` | unchanged | Copy exactly; never use it to fill `category_original`. |
| `demand.competent_entity_original` | unchanged | Copy exactly; it is a separate source dimension. |
| `demand` (no category) | `category_original`, `category_normalized` | Set both to null unless a later source extraction supplies the category. |
| `dialogue_event` | unchanged plus process link/date precision | Copy existing event fields; leave new fields null unless source evidence exists. A populated process link requires provenance for the link. |
| no mediation-process row | `mediation_process` | Create only from a process-level source record; do not manufacture one from an undated event. |
| `agreement.text_original` | unchanged as agreement/`Acuerdos` text | Copy exactly; document it as the agreement-text field. |
| no case-description field | `agreement.case_description_original` | Populate only from an explicit agreement-module `Descripción del caso`; otherwise null. |
| no follow-up field | `compliance_progress_original` | Leave null unless `Avances de cumplimiento` is explicitly present. |
| no responsibility/deadline fields | `responsibility_original`, `deadline_original` | Preserve explicit source strings only; do not link or interpret them. |
| `location.location_text_original` | unchanged plus structured originals | Copy full source text; populate department/province/district/population-center only from explicit source components. |
| `protest_event.event_date` | unchanged plus original/precision fields | Keep parsed date only when justified; preserve source date text and precision separately. |
| `violence_event.event_date` | unchanged plus original/precision/type fields | Keep parsed date/type derivatives nullable and preserve the source wording. |
| `report_month` | required `indicator_basis`, `scope_original` | Classify each row explicitly. Preserve any published scope; existing rows require review because v0.1 did not record origin. |
| `report` identity fields | evidence type and provenance fields | Do not promote embedded PDF `/Title` alone. Use document-visible and/or official metadata evidence; preserve conflicts. |

## Indicator migration

An old aggregate row cannot be safely classified from its metric name alone. During a
future migration, a human or deterministic source-unit review must set
`indicator_basis=source_reported` and provide provenance IDs for a published narrative or
table value, or set `indicator_basis=derived` with derivation name/version and upstream
record IDs. A derived value is a new row; it never replaces a source-reported row with a
matching metric/value. `provenance_ids` may additionally be retained on a derived row
when they document directly relevant source context, but derivation metadata and
upstream record IDs remain mandatory.

## Review triggers

Route the row to manual review rather than guessing when a source field is ambiguous,
when a date has no supported precision, when a process/event boundary is unclear, when
an organization could be either responsibility or actor, or when report number/month
evidence disagrees. Preserve both values and classify source contradictions separately
from parser errors.
