# Release versioning

Provisional sequence: v0.1 modern benchmark/foundation, v0.2 stable recent-format segment, v0.3 validated administrative overlap, v0.4 historical regimes, v0.5 2004-present candidate, and v1.0 first public research-grade release. Model schemas are retained under actual directories such as `schemas/v0.1.0/`; exporting a later schema version does not delete an earlier directory. Stable IDs use explicit scheme version `1` and a pinned golden vector before any canonical rows exist. Each release requires data, dictionary, schemas, code commit, source coverage/hashes, QA/benchmark evidence, known issues, adjudication summary, taxonomy version, changelog, checksums, citation, and licensing statement. Never overwrite a release. MIT covers repository software, not automatically source documents or derived-data redistribution rights.
