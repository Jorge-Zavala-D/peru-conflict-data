# Architecture

GitHub stores code, tests, schemas, config, docs, ADRs, repo-local skills, and small source-safe fixtures. The external data root stores official files, raw PDFs, mechanical extraction, parsed objects, linkage/geography, Parquet/DuckDB, QA/adjudication, and releases.

Active flow: `FIXED SOURCES -> REPRESENTATION/LAYOUT -> INDEPENDENT DISCOVERY -> FIELD/RELATIONSHIP CANDIDATES -> DETERMINISTIC VALIDATION -> CHALLENGE -> PI REFERENCE/AUDIT -> DERIVED CORRECTION -> FROZEN EVALUATION -> SCOPED EXPANSION -> PARQUET/DUCKDB -> PUBLIC RELEASE`. See [strategy](ai_pi_strategy.md), [reference/evaluation protocol](ai_pi_reference_evaluation_protocol.md) and [roadmap](ai_pi_roadmap.md).

Reuse scientific models/provenance, strict evidence/state/date validators, source references and deterministic metrics. The additive AI/PI module provides plan-only metadata and pure synthetic lifecycle validation; real extraction, decision persistence, discovery/relation evaluation and canonical materialization remain specific next-task seams, not implemented services. Native/layout/table methods and bounded model assistance are chosen by source evidence; OCR requires page-specific need.

Keep immutable PDF authority separate from representations, raw responses, initial candidates, source-first/assisted PI submissions, append-only adjudications, derived versions and frozen scores. Cache by actual source/code/config/schema/tool/model/prompt identity; retained-output reproducibility is not a promise of identical future model responses. Source packets exclude protected references and coordinator metadata. Each batch has source-unit coverage including unprocessed/empty pages, budget and a distinct owner execution decision. Qualification and release do not follow automatically from technical validity.
