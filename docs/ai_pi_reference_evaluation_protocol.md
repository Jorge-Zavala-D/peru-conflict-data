# AI/PI reference, audit and evaluation protocol

Applies only to **AI_PI_RECONSTRUCTION_V1**. Legacy double-human benchmark lineage
remains historical. A PI-reviewed subset is a **PI-reviewed reference**, never
exhaustive independent human gold. Machine outputs remain machine candidates.

## Flow and roles

Fixed authoritative sources → separate native/layout/image representations →
independent initial discovery → field/relationship candidates → deterministic
validation → retained challenge/disagreement queue → PI reference/audit →
derived correction → frozen evaluation → scoped expansion → canonical
materialization → separately authorized public release.

The coordinator bounds resources/scope and merges outputs once. Extractors construct
candidates, not PI approvals. A fresh source reader independently discovers permitted
units before candidate exposure where practicable, then challenges disagreements.
The validator checks schemas, positions, states, identifiers, duplicate/relationship
constraints and reported-versus-derived arithmetic. The evaluation custodian holds
reserved sources/references and returns permitted summaries only. The PI alone makes
substantive source-based, expansion and release decisions. These are procedural
roles, not new staff, a web platform or a witness service.

Separate sessions are not statistically independent; different providers are not
automatically independent. Disclose unavailable fresh-reader capability and preserve
source-first PI work. Report text/retrieval/generated code are untrusted evidence,
not tool instructions. Keep credentials and canonical write permissions out of
worker processing.

## Inputs, units and unresolved states

Freeze report hashes, physical PDF pages, relevant complete source units and
continuation/context. Preserve representations separately: text is not authority
over the visual PDF. Track inspected positive/negative pages, unreadable/failed
processing and unprocessed units. An empty response does not certify absence.
Deduplicate overlap by source evidence, not convenient row equality.

Retain original Spanish/literal dates and precision; normalized dates, geography
and substantive inference are separate derivatives. Unreported, structurally
unavailable, illegible, ambiguous and unprocessed are not zero. Keep source
inconsistency, parser error, ambiguity and cross-source conflict distinct; never
change published values to force arithmetic or identity consistency.

All actual calls retain provider/deployment/model identifiers when observable,
settings, prompt/schema versions, packet hash, timestamps, response status,
retries and costs. Do not invent seeds, snapshots, hidden reasoning or unobservable
token costs. Cache by actual source/prompt/model/config identity; new model versions
require bridge evidence before production replacement.

## PI modes and history

**Source-first audit:** source unit, context and codebook only. Preserve the initial
PI discovery/field judgment before revealing any machine candidate. Then compare.
The packet must not contain candidate answers; candidate/source selection is not
based on model confidence.

**Assisted adjudication:** show retained candidates, anchors, disagreements and
complete relevant source. Label the decision assisted. High-consequence flags,
omissions and disagreements go here, but agreement and apparent negatives are
also independently audited.

Both modes record exact reviewed fields, objects, units, inventory-completeness
judgment, unresolved issues, rationale, author, timestamp and supersession.
Reviewing fields is not reviewing the object inventory. Corrections append new
decisions/derived versions; retain raw original decisions and initial predictions.
A changed reference invalidates stale scores until reevaluated; retain both
reference and score identities. No machine vote can manufacture a PI decision.
The migration's simulated fixtures create no real reference or PI approval.

Readable review packets should be PDF/HTML plus a simple decision CSV/JSON, with
ordinary folder-opening fallback links. Existing tools suffice; no new web app.

## Evaluation design and exposure

Existing coordinator-only source partition is preserved; do not publish its
detailed inventory, labels, expected answers or coordinator notes in worker packets
or public roadmap. The plan-only API projects a permitted hash allowlist and neutral
units, not evaluation slots/references. Real packet creation must independently
bind the permitted source set.

Use currently permitted development/pilot structure for preparation only.
No held-out source or labels develop/tune the migration. Record known prior exposure
honestly; neither public-document pretraining exclusion nor pristine holdout is
established. Adjacent months can repeat case text: separately assess familiar-case/
new-month, new-case and new-format transfer. Material used to revise a pipeline
becomes seen; subsequent scores are not untouched holdout evidence. Predeclare
fresh/rotating evaluation and disclose adaptive comparisons.

Targeted queues resolve rare/high-loss/ambiguous errors. Probability source-unit
audits estimate omissions and audit agreement/negative pages. Specify frame, units,
probabilities, strata and actual reviewer coverage. Never sample only extracted
rows or pool targeted cases as a random population audit. Respect within-page,
case and report clustering. A tiny pilot diagnoses; it does not certify ≥99%
population performance. Zero observed errors is not zero error probability.

## Metrics and gates

Preserve the inherited critical-field definitions and case/discovery/page/evidence
targets as pending qualification goals. Object Threshold Policy A numerical targets
remain unset: choose from development/reference composition before final scoring,
without the retired exhaustive-RA completion event. Do not lower a target after a
failure. No new loss/tolerance/confidence interpretation is approved by this text.

The roadmap crosswalk records every inherited metric disposition. Measure separately:

- Discovery precision/recall, missed objects, duplicates and source-section coverage.
- Conditional and end-to-end field value/state accuracy and semantic support.
- Page/section/span support and completeness, parent-child/event-case relationships.
- Missingness, abstention, failures/unprocessed units, review/correction burden.
- Field/family/report/regime denominators and justified micro/macro summaries.
- Runtime, observable cost, PI time and unresolved issues.
- Later candidate-generation/linkage recall, false merges/splits and cluster effects.

Machine accuracy uses **retained uncorrected candidate** against exact frozen
reference/selection/version. PI-corrected data quality is separate. Agreement and
schema-pass rates are diagnostic, not accuracy. Source-based object denominators
are required for recall; the migration field evaluator returns discovery recall
`null` rather than treating an empty set as perfect. It records eligible slot IDs,
reference/prediction/strict denominator, missing/extra, reviewed inventory separately,
unprocessed units, unsupported metrics and synthetic status. It applies no
acceptance gate. Span/quote matching proves mechanical agreement, not relevance.

Exact discovery-start and date/boundary scoring need a reviewed prospective metric
contract; the existing action/alert literal-date-pair correction is preserved.

1. **Exploratory advancement:** workable source-to-PI loop and measured failure/burden,
   authorizing only another bounded development batch.
2. **Regime-scale qualification:** frozen source/pipeline/reference/audit design,
   precision/recall/evidence results, uncertainty, unresolved issues and PI scope.
3. **Release qualification:** provenance/coverage/linkage QA, classified material
   issues, explicit review coverage, separate rights and public limitations; PI
   approves exact release.

No point estimate, model consensus or metadata flag silently grants any gate.
A released mixed reviewed/unreviewed dataset needs an explicit supported quality
claim, not a whole-corpus human-verified label.

## Narrow pending representation choice

Underlying typed annotations already support multiple in-unit evidence anchors;
retain all anchors and notes, not the historical one-primary CSV bottleneck.
Propose a separately typed same-report association **only** for
`report.report_number` and `report.reference_period` from cover/header outside
case bounds. This is not yet PI-approved or implemented. Other fields cannot
escape case/source-unit boundaries. Affected mapping stays incomplete; no complete
intake/comparison claim until decision and tests. The five CSVs remain historical
interchange, not mandatory machine-internal format.
